Production engineering is about stability. Innovation requires experimentation. This is where theoretical models are tested before they touch production — and where failures are as valuable as successes.

  • /01

    WASM-Compiled RAG Execution

    Testing the latency and accuracy implications of running vector similarity search directly inside a browser using WebAssembly. The core question: can client-side retrieval eliminate the server round-trip for small knowledge bases without sacrificing retrieval quality?

    Early results show viable latency for knowledge bases under ~10k documents. Beyond that, server-side retrieval remains necessary. The experiment surface a clear boundary that now informs when to recommend client-side vs server-side RAG architecture in production systems.

    WebAssembly · Vector Search · Cosine Similarity · Browser Performance · Retrieval Architecture

  • /02

    Deterministic LLM Router Architecture

    An architectural prototype for routing LLM queries deterministically based on detected intent, rather than letting the model decide which tool or data source to use. The hypothesis: removing non-determinism from routing dramatically improves reliability in production AI systems.

    The prototype classifies incoming queries into intent categories (structured lookup, semantic search, summarization, generation) and routes each to a pre-defined handler. This produces auditable, predictable behavior — a prerequisite for enterprise deployment where black-box decision-making is unacceptable.

    Intent Detection · Query Routing · Determinism · LLM Architecture · Enterprise AI

  • /03

    Self-Healing Data Pipelines via Semantic Drift Detection

    Researching autonomous data pipelines that detect when incoming data has semantically drifted from expected patterns and self-correct their processing rules without human intervention. Traditional pipelines break silently when schemas or content patterns shift — this experiment builds a detection and correction loop.

    The approach uses embedding distance monitoring between incoming data batches and a baseline corpus. When drift exceeds a threshold, the pipeline triggers a re-mapping process. Early experiments show this reduces silent data corruption in long-running ingestion jobs significantly.

    Data Pipelines · Semantic Drift · Embeddings · Autonomous Systems · Ingestion Architecture

  • /04

    Role-Aware RAG Access Control Prototype

    A prototype demonstrating how retrieval-augmented systems can enforce fine-grained access control at the document level, not just the API level. Standard RAG systems retrieve from a shared vector store — this approach partitions retrieval by user role, office, and permission scope before any data reaches the LLM context.

    Built as a middleware layer that intercepts retrieval requests, enriches them with role metadata from the auth system, and filters the vector store query accordingly. This ensures no user can receive information outside their permission boundary regardless of how they phrase their query.

    RAG · Access Control · Role-Based Security · Vector Store Filtering · Enterprise AI · Middleware

  • /05

    Edge-Device LLM Orchestration

    Researching the viability of running lightweight LLM inference and orchestration logic on low-power, memory-constrained devices. The goal is understanding where AI inference can move to the edge — reducing latency, increasing privacy, and eliminating cloud dependency for certain use cases.

    Experiments focus on quantized model performance, memory-safe orchestration pipelines, and the trade-offs between model capability and compute constraints. Early findings indicate that routing and retrieval logic can often run at the edge effectively, even when generation must remain server-side.

    Edge AI · LLM Inference · Quantization · IoT · Memory-Safe Systems · Orchestration

  • /06

    Parallax UI Architecture Experiment

    A frontend engineering experiment merging two fundamentally different scroll architectures into a single unified page experience. The challenge: luxy.js uses fixed positioning and CSS transform translation for smooth scroll, while a second portfolio used native browser scrolling with IntersectionObserver and GSAP ScrollTrigger.

    The solution required building a JavaScript sticky position simulator that calculates section offsets in real-time and applies counter-translations to preserve sticky behavior within the luxy.js wrapper. The result is a seamless merged scroll experience with zero layout regression — the system this website runs on.

    GSAP · luxy.js · ScrollTrigger · JavaScript · CSS Transform · Scroll Architecture · Frontend Engineering
